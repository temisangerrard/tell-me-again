Building Tell Me Again

Tell Me Again helps a family record the stories their parents and grandparents carry, one question at a time. This page shows how it was built with an AI coding assistant: the working loop, the decisions I made myself, what the AI got wrong, and what caught it.

62commits, 3 to 4 November 2026
22pull requests, each on its own branch
102automated tests, all passing
101hand-written interview questions

Counts come from the git history and the test run. The app has no build step: about 4,000 lines of JavaScript and 900 of CSS, plus a small Cloudflare Worker.

How the work went

One loop, repeated

Every feature, from the avatar maker to sign-in, went through the same six steps. The AI did the typing. I did the deciding, and I kept the one irreversible step for myself.

  1. I describe a feeling or a goal in plain words"It looks naked." "It doesn't flow." No file names, no specs.
  2. The AI proposes, then builds on a branchIt explains the options and gives a recommendation. For big changes it writes the plan into the repo first.
  3. It checks its own workAutomated tests, then the real thing: a browser for the screens, a local server for the backend, a real recorder for audio.
  4. I look at it and say what is wrongThis is where most of the good changes came from. The AI could not have known the characters felt off.
  5. A second reviewer reads the pull requestAn automated code reviewer on GitHub (Codex) comments on the diff. The AI fixes what is real and closes each thread.
  6. Only my exact words ship it"Merge and deploy" is the phrase. Nothing goes to the live site without it, and the tooling enforces that.

The human part

What I said, and what changed

The AI is good at building and bad at taste, so taste was my job. These are my actual messages, lightly cleaned of typos, next to what they led to.

On the hand-drawn characters“I love everything except how the characters look.” Then: “Invoke Blender or something.”
What changedThe AI had drawn the cast as flat vector art. I rejected it, and also named the tool. It built a clay-style 3D cast with a script in headless Blender, rendered as small animated images.
On the writing“Anything that sounds like ‘it’s not this, it’s that’ is AI copy.”
What changedIt rewrote the landing page copy, then turned the rule into a test. The question bank now fails the build if it contains em dashes or that sentence pattern.
On the Sit page“It looks naked. People won’t know what to do in the app.”
What changedA visible three-step path for the first story: add someone, ask a question, keep it. It stays until the first recording exists.
On the product itself“I don’t want an AI interviewer. Let the AI suggest what the asker asks. This is a relationship-building tool.”
What changedThe plan was rewritten straight away. A person always asks and a person always answers. The AI only reads the written story and suggests questions to the person asking.
On recording“The start and stop of the interview is ugly. It does 3, 2, 1, then records, then doesn’t ask the next question. It doesn’t flow.”
What changedOne start, no countdown. A Next question button cuts the audio and carries on, and each answer is saved as its own recording. Calls got the same treatment.
On the Family tab“Put things into accordions so it’s neat. You won’t make an avatar daily.”
What changedRarely used settings fold away. The avatar shows as a small thumbnail until you open it.
The honest part

Where the AI got it wrong

It makes real mistakes, quietly and with confidence. Nothing here was caught by the AI trusting itself. Each one was caught by something outside it.

Real-world check

A retired AI model

The lore feature called a model Cloudflare had retired. The unit tests passed because they used a stand-in. A single call to the real service failed straight away. Lesson: test against the real thing before you ship.

Test

Audio saved too early

The continuous recorder saved each answer before the browser had handed over the last piece of audio. A test with a fake recorder failed on exactly that, and the fix was one line of ordering.

Code review

Backups that lost data

The reviewer noticed that restoring a backup silently dropped avatars. The AI then found it also dropped the whole people list, an older bug nobody had seen.

Code review

A way round the tester list

Asking for a code in one mode and verifying it in another let an unlisted email create an account. The fix moved the check to the point where the account is created.

Code review

The wrong question for the person

When someone had covered every topic, the app asked the next question using the previous person's relationship to you. A sibling could get a grandparent question.

Deploy output

An address that went dark

Adding the custom domain turned off the old address, which broke shared links. The deploy output said so. The tooling then blocked a second, unapproved deploy, so the AI stopped and asked me.

User

Sign-in that looked broken

It worked, but showed no confirmation, so it looked like a refresh. Only a person trying it could see that. Now it says "You're in" and moves on.

What kept it steady

Rules that did the boring work

  • Write it down before building. Plans live in the repo (docs/plans/). When I changed direction on the AI interviewer, the plan changed first, so later work followed the new decision.
  • Keep rules where the AI reads them. The README and an instructions file hold the standing rules: no tracking tools without my decision, audio stays on the device, bump the privacy version when the notice changes.
  • Turn taste into tests. Copy rules, bank structure and the privacy promise are checked automatically, so a future change cannot quietly undo them.
  • One branch, one pull request, one purpose. The main branch is protected, so every change gets a second look and can be undone cleanly.
  • Gate the irreversible step. Deploys, merges and anything that touches money or accounts waits for an exact phrase from me.
Things worth copying

Prompts that worked

Describe the feeling, not the fixIt looks naked.The AI then proposed three concrete changes and I picked one. A specific order would have fixed the symptom and missed the cause.
Say what you refuseI don’t want an AI interviewer.One sentence of what you will not accept saves a week of building the wrong thing.
Name the tool, leave the method openInvoke Blender or something.I did not know how to model characters in code. I knew which program could. The AI wrote the script.
Think before you buildLet’s brainstorm a punchy name.Asking for options and a recommendation first kept me from steering the build with an idea I had not examined.
Make it durableWrite this down.A decision in a chat disappears. A decision in a file in the repo is there the next time.
Give permission in a fixed phraseMerge and deploy.The AI asks every time and ships only on those words. It stops it from treating "looks good" as a go-ahead.
Under the hood

What it is made of

No build stepPlain HTML, CSS and JavaScript files. Easy for an AI to read whole, and easy for you to open.
Cloudflare WorkerRooms for family games, call setup, sign-in, and a few small endpoints. Durable Objects hold live state.
Speech to textCloudflare's speech model turns recordings into editable text, after the person says yes.
A small language modelReads a written story and lists people, places, years, foods and sayings. It suggests questions, and never speaks to the person being interviewed.
Blender, from a scriptThe 3D cast and the avatar layers are rendered by a Python script, no downloaded models.
Tests in Node102 tests, many running the whole app in a simulated browser, plus real-browser checks for what a simulation cannot show.
If you are starting

Five things I would tell you

  • You are the product owner, not the typist. Your value is knowing what is wrong and what you refuse. Say it plainly and often.
  • Trust nothing the AI says about its own work. Run the tests. Open the real screen. Call the real service.
  • Add a second reviewer. An automated reviewer on every pull request found five real bugs that the AI and its tests had missed.
  • Keep the work small and in writing. Short branches, plans in the repo, rules in a file the AI loads each time.
  • Ship to people early. Feedback was "great idea, we don't like the games". That one line shaped more than any feature I added.
